# 祝日法の制定・初回改正 再構築試行手順

作成日: 2026-11-16。本文データの変更前に作成。

## 対象と成果物

- 国民の祝日に関する法律の制定時（昭和23年法律第178号）と、昭和41年法律第86号による改正後の2版を作る。
- 制定時の官報正誤は同じRevisionの訂正として扱う。建国記念の日の日付欄は改正本文の「政令で定める日」を保存し、後の政令の具体的日付を本文へ代入しない。
- 法令リポジトリに history.yaml、rebuild.yaml、2版の versions/、調査・検査記録を作る。登録台帳に本法と改正法のRecordを記録する。改正法の全文収録は今回の対象外。
- 今回はローカルの作業ブランチで試行する。リモート公開・既定ブランチ切替・mainへのマージは行わず、試行完了と本移行を区別する。

## 実行手順

1. **現状を固定する。** 両法令・台帳・仕様・検査器のHEAD、ブランチ、作業ツリー状態を記録する。祝日法の旧masterの完全ハッシュを凍結点として控え、既存ブランチと全履歴を保持したまま専用作業ブランチを作る。既存の利用者変更には触れない。
2. **仕様と検査器を確認する。** CONTRIBUTINGと関連運用文書、loj/v1alpha2、history・registry・glyphs・rebuildの規範を読む。検査器の固定仕様と現行仕様の差を確認し、既存の正常ケースで動作を確かめる。仕様内の祝日法の試作は書式・資料探索の参考であり、今回の照合済みデータとして複写しない。
3. **原典を取得・確認する。** 制定官報第6453号（1948-07-20、NDL pid/2962986）、正誤官報第6512号（1948-09-28、pid/2963048）、改正官報号外第78号（1966-06-25）を探索する。官報を取得できない場合のみ国立公文書館の御署名原本（file/130738、file/686000）を使う。画像の閲覧範囲、URL、取得日、保存ファイルのSHA-256、判読不能箇所、正誤調査範囲を調査記録に残す。未閲覧資料を確認済みとしない。
4. **登録と履歴を作る。** Record IDは既存の19480720-law-178、19660625-act-86を保持する。revision_idはCrockford Base32小文字8字をランダム発行し衝突確認する。番号・公布・施行・改正関係を原典の該当箇所に結び付ける。改正は同一施行時点の3行追加として一つのRevisionにまとめる。収録範囲はunconfirmedとする。
5. **制定版を起こす。** 本則3条と制定附則を原典から転記する。祝日の列挙は表とし、原典にない見出し・リンクを持ち込まない。官報正誤の修正を反映して根拠を記録する。文字正規化・新旧字体の一括変換を行わず、曖昧な字はglyphs.yamlへ記録する。
6. **初回改正を適用する。** 制定版を基礎に、改正原典の指示に従って建国記念の日・敬老の日・体育の日の行だけを加える。変更されない文字列と制定附則を保持する。改正法自身の附則は被改正法本文へ追加せず、施行等の根拠として履歴で参照する。
7. **旧本文との差を記録する。** 実際の旧commitと版の対応を調べ、表の構造、字体、附則見出し等の差をrebuild.yamlへ記録する。試作時以降の旧履歴も確認してpendingを更新する。未確認の字体、官報未取得、正誤調査不足を明示する。
8. **検証する。** 各版をL0・L1、本法をL3 historyStructure/evidence、台帳をregistry、関連RecordをL4、再構築報告をrebuildとして独立に検査する。JSON結果と実行コマンド、検査器・仕様commitを保存する。本文差分で追加3行以外の変更がないこと、旧ブランチ先端が不変であることを確認する。ディレクトリ検査は正本commitへの適合認証とは区別する。
9. **結果をまとめる。** 実施済み項目、2つのrevision_id、根拠資料、検査結果、未解決事項、本移行に残る作業を日本語で記録する。官報との照合未完了ならglyphCheckはunverified、原典を全く取得できない版はabsentにする。形式検査合格を原典一致・全文履歴の網羅の証明としない。

## 完了条件

2版と関係・登録・再構築記録が検査可能な形で揃い、実行結果と原典照合の限界が明示されること。原典取得不能時も推測の本文を完成品とせず、欠落を仕様に沿って記録し、試行の結果として報告する。
